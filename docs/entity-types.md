# Week 11 — entity type contract (schema version 1)

All entity IDs are UUIDs generated by the canonical store. Entity identity is
distinct from a mention: each mention retains its source evidence and proposed
canonical entity. Extraction confidence describes the extractor's confidence;
it is not proof that a proposed identity is correct.

## Common envelope

| Field | Type | Rule |
| --- | --- | --- |
| `entity_id` | UUID | Stable identifier for this canonical entity |
| `entity_type` | enum | `person`, `topic`, or `decision` |
| `display_name` | string | Human-readable label; non-empty |
| `aliases` | string[] | Observed names/phrases, not independent identity evidence |
| `status` | enum | `active`, `needs_review`, `superseded` |
| `confidence` | number 0..1 | Extraction/resolution confidence, with producer recorded |
| `evidence` | EvidenceRef[] | At least one exact `(segment_id, revision)` reference |
| `created_at`, `updated_at` | timestamp | UTC timestamps |

EvidenceRef follows Week 8: `segment_id`, `revision`, optional `start_ms` and
`end_ms`. Derived entity claims are immutable versions; material source
revision changes mark dependent claims `needs_review`.

## Person

Additional fields: `person_id` (same as `entity_id`), optional `verified_name`,
`resolution_status` (`unresolved`, `candidate`, `confirmed`), and optional
`session_speaker_refs` (`session_id`, `speaker_label`). Speaker labels remain
session-local. Matching a name or `SPEAKER_01` across sessions never alone
confirms a person; confirmation requires explicit evidence or user resolution.

## Topic

Additional fields: optional `description`, `parent_topic_id`, and `keywords`.
Topic identity is a normalized subject/concept, not an individual mention.
Parent links must not create cycles; ambiguous merges remain separate pending
review.

## Decision

Additional fields: `statement`, `decision_status` (`proposed`, `accepted`,
`reversed`, `superseded`), optional `decided_at`, and optional `supersedes_id`.
A decision is a claim about an outcome, distinct from a topic and from an
action to carry it out. `accepted` requires supporting evidence; uncertainty
remains explicit in confidence and evidence.

## Example

```json
{
  "entity_id": "7cd88d30-f665-4f52-a623-994c7ae103c4",
  "entity_type": "person",
  "display_name": "Priya Sharma",
  "aliases": ["Priya"],
  "status": "active",
  "confidence": 0.88,
  "resolution_status": "candidate",
  "session_speaker_refs": [{"session_id": "session-1", "speaker_label": "SPEAKER_02"}],
  "evidence": [{"segment_id": "segment-42", "revision": 2, "start_ms": 84120, "end_ms": 90680}]
}
```

## WEEK OUTPUT CONTRACT

**Input:** Garvit-style extracted mentions and Week 8 revision-aware transcript
evidence (currently treated as a replaceable producer contract).

**Output:** Version-1 entity candidates for people, topics, and decisions;
every candidate carries exact evidence references and an explicit resolution
state. No cross-session identity is inferred from a speaker label alone.
